# 온길 · 교회 헌금 웹

**화면 시연:** https://lpseonggyeong-source.github.io/church-demo/ (저장·결제는 동작하지 않는 보기 전용 사본)

Python 3.9 이상과 SQLite를 사용합니다. 별도 패키지 설치 없이 서버와 브라우저를 실행할 수 있습니다.

## 팀원용 빠르게 보기

```sh
git clone https://github.com/lpseonggyeong-source/church-demo.git
cd church-demo
PAYMENT_MODE=mock python3 app.py
```

## 화면 흐름

- 성도 · 교회 선택 또는 교회 전용 주소 → 성경책 → 장 → 절 → 본문
- 헌금 · 항목과 금액 → 입력 내용 확인 → Mock 결제 → 결과 (성도용 헌금내역 화면은 두지 않음)
- 키오스크 · 시작 → 항목·금액(숫자 키패드) → 확인 → 카드 결제(테스트) → 완료, 모두 익명
- 교회소식 · 공개 공지 목록 → 상세
- 관리자 · 개발용 계정 로그인 → 헌금 내역(필터 · 합계) · 교회 설정(교회 정보, 로고, 홈페이지 주소, 헌금 항목 순서, 공지)
- 운영자 · 개발용 계정 로그인 → 교회 추가와 교회별 관리, 번역본 메타데이터 관리, PG 모드 확인

## 실행

압축을 풀고 `ongil` 폴더에서 `python3 app.py`를 실행한 후 브라우저에서 http://127.0.0.1:8765 를 엽니다.

개발용 교회 관리자 비밀번호는 `demo-admin`, 운영자 비밀번호는 `demo-operator`입니다. 성도 내역은 현재 브라우저의 비공개 세션으로 조회합니다. 결제 결과에 표시되는 비공개 조회 코드를 보관하면 다른 브라우저에서 해당 거래를 조회할 수 있습니다. 이름을 입력하면 새 헌금에 저장하며 담당 교회 관리자 화면에 표시합니다. 이름을 비우면 익명으로 기록합니다. 이전 내역의 이름은 소급할 수 없어 이름 기록 없음으로 표시합니다. 연락처와 메모는 확인 화면에서 보여주며 저장하지 않습니다. 관리자 화면에서 이름, 일자, 상태로 내역을 조회할 수 있습니다. 일시는 한국 시간 기준이며 결제 완료 시각이 없는 건에는 접수 시각을 표시합니다.

환경 변수 목록은 `.env.example`을 참고하세요. 실행 전에 셸 환경으로 설정합니다. 개발 서버는 로컬 주소에만 바인딩합니다.

## 사내 PG 연결

`payments.py`의 PaymentProvider가 호스티드 결제 세션 생성과 이벤트 검증 경계입니다. 서버는 교회와 활성 헌금 항목, 원화 금액을 검사한 후 주문을 생성합니다. Mock 이벤트도 거래 식별자, 금액, 서명과 상태를 확인합니다. 결제 시작 요청은 세션별 요청 키로 중복을 막고 완료된 상태는 다시 적용하지 않습니다.

### 링크페이먼트 카드 테스트

카드 결제 샘플의 `paynix.pay`를 연결했습니다. 기본은 Mock입니다. PG 담당자에게 **테스트 단말기에 발급된 3DS 공개 결제키**인지 확인한 뒤 다음처럼 실행하세요.

```sh
export PAYMENT_MODE=linkpayment-test
export LINKPAYMENT_TEST_PUBLIC_KEY='확인한 테스트 공개 결제키'
export LINKPAYMENT_TEST_TERMINAL_CONFIRMED=yes
python3 app.py
```

샘플은 SDK의 `debugMode=live`를 고정값으로 명시합니다. 테스트 환경을 결정하는 것은 이 값이 아니라 PG 담당자가 확인한 테스트 단말기입니다. 샘플에 들어 있던 키는 패키지에 포함하지 않았습니다.

헌금 내용을 확인한 뒤 **링크페이먼트 결제창 열기**를 누르면 서버가 주문 금액, 헌금 항목, 온길 주문번호(`udf1`)를 발급합니다. 한 주문의 결제창 열기 요청은 한 번만 허용합니다. 브라우저 콜백은 화면 안내에만 사용하며 카드 정보와 콜백 원문은 저장하지 않습니다.

샘플에는 **서버 거래 조회 API 또는 서명이 있는 웹훅을 검증하는 규격**이 없습니다. PG 결제창이 성공을 알리더라도 온길의 헌금 내역과 관리자 화면에서는 처리 중으로 표시됩니다. 승인 결과를 확정하려면 PG 담당자에게 테스트 서버의 거래 조회 URL·인증 방식·응답 예시 또는 웹훅 서명 규격을 받아 주문 식별자·단말기·금액과 대조하도록 연결해야 합니다.

## 성경 데이터

성경 화면은 [Open Korean Bible](https://github.com/open-korean-bible/open-korean-bible)의 원문(`original`)을 표시합니다. 전권 파일과 설치 과정에서 각 절의 번호와 원문만 보관합니다. 번역자는 **기완**이며 라이선스는 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)입니다. 본문 내용은 유지하고 원본의 고유명사 표기 `{{…}}`를 굵은 글씨로 표시합니다.

### 전권 설치

패키지에 `bible_all.json`이 없으면 `ongil` 폴더에서 다음 명령을 한 번 실행한 뒤 앱을 다시 시작하세요.

```sh
python3 okb.py
```

인터넷 연결이 없는 환경에서는 [GitHub 합본 파일](https://github.com/open-korean-bible/open-korean-bible/blob/main/data/bible_all.json)을 다른 기기에서 받아 `python3 okb.py /path/to/bible_all.json`으로 설치할 수 있습니다. 전권 파일을 설치하기 전에는 원본 README에 제공된 창세기 1:1 미리보기를 표시합니다.
